> So, next time when I need to deploy servicex with a different EOS storage element - let's say eos.cms.cern.ch - and possibly with a
  different path, not /store/user/piperov - where should I change these parameters? What file carries these settings currently?

  You should make these changes directly in your custom configuration file: values_local-k3d_CMS.yaml.
  
  Currently, this file contains the following block:
  
    objectStore:
      enabled: true
      type: eos
      internal: false
      eos:
        host: eos.cms.rcac.purdue.edu       # <-- Change this to "eos.cms.cern.ch"
        protocol: root
        pathPrefix: /store/user/piperov     # <-- Change this to "/your/new/path"
        useBucketDirectory: "true"
  
  ### How it propagates:
  
  When you run  helm upgrade --install ... -f values_local-k3d_CMS.yaml :
  
  1. Helm updates the storage-configmap.yaml in the cluster.
  2. The  servicex-app  pod automatically detects the ConfigMap update and updates its internal storage settings.
  3. When the app dynamically spawns transformer sidecar pods, it passes the updated environment variables to them.
  
  No changes to Python source code or Docker images are required when updating these settings!
